# 推广方案：把 Input 试点的规格推到其余页面

日期：2026-10-23。规格来自 `2026-10-22-pilot-input-and-errors.md`（修订版）。这份只是方案，确认后再动手。

## 每页都要做的五件事

1. **顺序**：
   - 场景 demo 放在页面最前，When to use 压到三行以内。
   - 然后是 Details，再往后是参考层：Variants（或 Kinds）、Anatomy、States。
   - 页面末尾放 Known issues（有才写）、Common mistakes、Copy。
2. **场景的标签只写场景名，不写操作说明。**
   - 现在不少标签在教读者怎么操作，比如 “Live · type “sao”, “zur” or a country, then Enter”“Live · Tab in, then arrows choose”。这就是“此地无银”，统一改成场景名：“Time zone”“Export”。
   - 场景要作用在一个真实的东西上：一张画布、一份列表、一个读数。
3. **说明重写**：只写 demo 本身看不出来的东西——原因、出处链接、什么情况下不适用。删掉复述画面的句子。
4. **静态的几何关系从对比里挪出来**，改成 Anatomy 里的标注图。
5. **每对 Before/After 只差一个地方。** 夸张的、一次改了好几处的 Before 要收窄。Before 如果能对上一个真实产品，就在说明里放出处链接；没核实的不写产品名。

## 归纳出来的原则页候选（这一轮只列，不做）

组件页上的规则，有几组背后是同一个机制。以后做成原则页，组件页就链过去：

| 候选 | 机制 | 用到它的组件 |
|---|---|---|
| **Colour means one thing** | 一种视觉特征只表达一个意思，否则就变成组合搜索 | Tabs 的指示条用墨色、Segmented 用浮起而不用蓝色、Toolbar 当前工具只着淡色、Select 用对勾而不用底色、Badge 和 Toast 颜色只放在图标上 |
| **Motion has a source** | 东西从哪里来、回哪里去，读者就不用找 | Menu、Popover、Select、Dialog、Toast |
| **The more often, the less motion** | 高频操作上的动画，每次都要付注意力 | Button 的 hover、Menu、Tooltip 的分组、命令菜单 |
| **Nothing shifts** | 布局一跳，读者就要重新找位置 | Tabs 选中不变粗、Slider 数字等宽、Button 加载时宽度不变、Card 数字切换 |
| **Undo instead of asking** | 确认框会被习惯性点掉 | Toast、Dialog |
| **The target is the whole thing** | 目标越大越好点（Fitts） | Checkbox 的标签、Slider 的整行、Card 整张可点 |

## 节奏

- 每批 3–4 页，一批一次部署。
- **第一批**：Button、Badge、Toast、Checkbox。前两页要新做场景，后两页主要是调整顺序和收窄 Before。
- **第二批**：Menu、Dialog、Popover、Select。都和“从哪里长出来”有关，做完正好为 Motion has a source 积累素材。
- **第三批**：Radio、Switch、Tabs、Segmented control。
- **第四批**：Slider、Card、Table、Toolbar、Tooltip、Combobox。

## 要你决定的

1. **按批来，每批部署一次**，还是全部做完再一起上线？我推荐按批。
2. **原则页**：等组件页全部推完再做，还是穿插着做？我推荐第二批之后先做 Colour means one thing，因为它牵涉的组件最多。
3. **Button 和 Badge 的新场景**，用上面写的“文档顶栏”和“issue 列表”可以吗？
