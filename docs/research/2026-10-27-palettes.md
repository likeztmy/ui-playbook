# Selectable accent palettes

Research for an "Appearance" popover that offers three or four accent palettes beside today's blue. Only the five accent tokens change per palette (`--accent`, `--accent-hover`, `--on-accent`, `--accent-soft`, `--accent-text`, light and dark). Constraints from the owner: the alternatives should read as an editorial product, not a SaaS console, and no purple, violet, indigo, iris, plum or lavender.

How colour is *used* is covered by `src/pages/principles/colour-means-one-thing.mdx`. How scales are *built* (OKLCH, the 0.02 ΔEOK JND, APCA, CVD matrices) is covered by `2026-10-27-colour-system.md`. Neither is repeated here.

**Labels.**
- **Verified**: read in the primary source this session (page text, CSS, source code, package files).
- **Computed**: worked out here from published formulas. OKLab uses Ottosson's 2020 matrices. WCAG 2 uses relative luminance. APCA uses 0.0.98G-4g; the implementation reproduces #888 on #fff = Lc 63.06 and #000 on #fff = Lc 106.04. CVD simulation uses the Machado et al. 2009 severity-1.0 matrices, as in `2026-10-27-colour-system.md`. Scripts lived in the session scratchpad and are not in the repo.
- **Unverified**: from memory or a secondary page; keep it off site pages.

APCA Lc is signed. Positive means dark text on a light background; negative means light on dark. Thresholds from *APCA in a Nutshell* (https://git.apcacontrast.com/documentation/APCA_in_a_Nutshell.html, **Verified**):
- Lc 75 is "the minimum level for columns of body text".
- Lc 60 is "the minimum level recommended for content text that is not body, column, or block text".
- Lc 45 is "the minimum for larger, heavier text".

## 1. Why purple and indigo became the default AI/SaaS accent

The evidence comes in four primary pieces. Each is a default that someone else shipped, which then became the median of what models learned from.

1. **Tailwind UI's buttons were indigo.**
   - Adam Wathan, creator of Tailwind CSS, posted on 7 Aug 2025: "I'd like to formally apologize for making every button in Tailwind UI `bg-indigo-500` five years ago, leading to every AI generated UI on earth also being indigo." The post had about 1.5 M views and 22 k likes. Source: https://x.com/adamwathan/status/1953510802159219096, read through the public embed mirror `api.fxtwitter.com`. **Verified.**
   - The Tailwind UI public preview page, archived 5 Jul 2022 (https://web.archive.org/web/20220705215051/https://tailwindui.com/components/preview), is consistent with the post. Counting `bg-/text-/ring-/border-` colour classes: gray 2,306, **indigo 748**, red 20, green 6. Indigo is the only chromatic family used for interaction. The most common fill is `bg-indigo-600` (53 times), then `bg-indigo-700` (36). **Verified** (computed count). The tweet says `500`; the page mostly used `600`.
   - In Tailwind v4, `indigo-500` is `oklch(58.5% 0.233 277.117)` and `indigo-600` is `oklch(51.1% 0.262 276.966)` (https://unpkg.com/tailwindcss@4.1.11/theme.css). **Verified.**
2. **Model makers name it as the tell.**
   - Anthropic's Claude Cookbook, *Prompting for frontend aesthetics*: "Clichéd color schemes (particularly purple gradients on white backgrounds)". Also: "Without guidance, Claude often defaults to simplistic designs with white and purple backgrounds." Source: https://github.com/anthropics/claude-cookbooks/blob/main/coding/prompting_for_frontend_aesthetics.ipynb. **Verified.**
   - Anthropic's `frontend-design` skill, Dec 2025 version: "NEVER use generic AI-generated aesthetics like … cliched color schemes (particularly purple gradients on white backgrounds)". Source: https://github.com/anthropics/skills/blob/00756142ab/skills/frontend-design/SKILL.md. **Verified.**
   - **Relevant to our candidates.** The current version of that skill (commit 41bbe19d1a, 3 Sep 2026) lists the *new* AI clusters. The first is a cream background with "a terracotta or warm-clay accent (often near #D97757 — Anthropic's own Claude-interaction accent, so on a user's brief it reads as a tell)". The second is "a near-black background with a single bright acid-green or vermilion accent". Source: https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md. **Verified.** Terracotta has therefore become the next cliché, and it also collides with danger (§3).
3. **Component kits default to indigo or purple.**
   - Radix Themes: `accentColor: { type: 'enum', values: accentColors, default: 'indigo' }`. Source: https://unpkg.com/@radix-ui/themes@3.2.1/src/components/theme.props.tsx. **Verified.**
   - Material 3's baseline scheme in Flutter: `primary: Color(0xFF6750A4)` (https://raw.githubusercontent.com/flutter/flutter/master/packages/flutter/lib/src/material/theme_data.dart). The `flutter create` template seeds `ColorScheme.fromSeed(seedColor: Colors.deepPurple)` (https://raw.githubusercontent.com/flutter/flutter/master/packages/flutter_tools/templates/app/lib/main.dart.tmpl). **Verified.** `#6750a4` is `oklch(0.496 0.130 293.7)`. **Computed.**
   - **Counter-example.** shadcn/ui's default is *not* purple. Its base colour is `neutral`, with `--primary: oklch(0.205 0 0)` in light and `oklch(0.922 0 0)` in dark (https://ui.shadcn.com/docs/theming). **Verified.** Avoid the common claim that "shadcn made everything purple".
4. **Product brands in the same space.** Linear's live CSS (static.linear.app, fetched 27 Oct 2026) has `--color-indigo:#5e6ad2`, `--color-accent:#7170ff` and `--color-brand-bg:#5e6ad2`. **Verified.** These sit at OKLCH hue 275–279°. **Computed.**

**Where "purple" sits in numbers.** All of these land at OKLCH hue 275–294°:

| Colour | Hex | OKLCH hue |
| --- | --- | --- |
| Tailwind indigo | `#6366f1` / `#4f46e5` | 277° |
| Linear | `#5e6ad2` / `#7170ff` | 275–279° |
| Radix indigo / iris / violet step 9 | `#3e63dd` / `#5b5bd6` / `#6e56cf` | 267° / 278° / 288° |
| M3 baseline | `#6750a4` | 294° |

Our blue (256°) is 20° short of Tailwind indigo. **Computed.** A rule of thumb for the site: no accent between 265° and 335°.

**A side note on today's neutrals.** The site's ink, `#18181b`, is exactly Tailwind v4 `zinc-900`, `oklch(21% 0.006 285.885)`. So every neutral sits at about 286°, the violet side, but at chroma ≤ 0.006, which no one can see. This is harmless, and a cause for the optional neutral step in §6.

## 4. The palettes: all values and contrast

**How the values were built.** **Computed.** The shape follows today's tokens:
- `--accent` is the darkest step at that hue that keeps white text ≥ 4.7:1 (today's Blue is 4.70:1).
- `--accent-hover` is 0.045 L darker.
- `--on-accent` is white.
- Dark mode keeps the light fill instead of a brighter one. `precision.json` records why: a brighter fill with dark text passes WCAG but gets only Lc 40 in APCA.
- `--accent-soft` is L 0.955 / C 0.03 in light and L 0.27 / C 0.045–0.05 in dark.
- `--accent-text` must reach ≥ 4.8:1 on every surface, including `--accent-soft`, as `precision.json` asks. Dark mode also has to reach |Lc| ≥ 60 on every surface.
- Ink is set by hand from the existing neutral ramp.

## 5. Things outside the five tokens that a palette switch touches

Found while reading the code; none of it was edited.

1. **`--focus-ring` hard-codes blue.** It is `0 0 0 2px …, 0 0 0 4px #0071e3`, and `#0a84ff` in dark. A palette switch leaves the ring blue unless the generator (`scripts/build-tokens.mjs` / `src/tokens/precision.json`) derives it from `--accent`. Its usage note already says "2px 实心 `accent`" (a solid 2px accent ring).
2. **Ink in dark mode makes the Switch knob invisible.** `--knob #f4f4f6` sits on `--accent #ececef` in the checked state (`src/ui/Switch.module.scss`): 1.07:1. Ink dark needs either a knob that follows `--on-accent` (`#0e0f11`) or its own `--knob` override.
3. **`--info` aliases `--accent-text`, and `--info-soft` aliases `--accent-soft`.** Under Ink, info callouts become grey. Under Petrol and Moss, they take the palette hue. That is consistent with the "info = the link colour" note in `precision.json`, but decide it on purpose.
4. **Places where `--accent-text` is the only signal:** `src/ui/Toolbar.module.scss` (the current tool's icon), `src/ui/Menu.module.scss` (the check mark), `src/components/hero/hero.module.scss`, `src/pages/index.module.scss` and `src/demos/*`. Under Ink the "current tool" becomes ink against ink-muted icons. That is still a difference, but a weaker one. The toolbar's `--tool-current` tint mixes in `--accent` and carries the rest.
5. **Ink's selection tint is faint.** `--accent-soft #e2e2e6` is 1.13:1 on `--surface-sunken`. Blue's soft tint is about as close in luminance, but its hue carries it. A grey selection has no hue to help.
6. **Finding about the current Blue.** Dark `--accent-text #2997ff` passes WCAG (5.46:1 or better) but gets only **Lc −42 to −45** in APCA on every dark surface. That is below Lc 60, the floor for "content text that is not body text", and links are read inline in 17 px prose. A text step that reaches Lc 60 at the same hue (OKLCH 252°, C 0.15) is `#7dbbff`: 8.17:1 and Lc −61.4 on `--surface-raised`. Out of scope here, but worth a decision while the palettes are built.

## 7. Reference pattern for the picker

- **Radix Themes `ThemePanel`.** Source: https://unpkg.com/@radix-ui/themes@3.2.1/src/components/theme-panel.tsx. **Verified.**
  - A panel fixed at the top right (`position="fixed" top="0" right="0"`), titled "Theme". `T` shows and hides it; `D` toggles light and dark.
  - Sections in order: Accent color, Gray color, **Appearance** (Light and Dark as two radio cards with sun and moon icons), Radius, Scaling, Panel background. Palette and mode live together.
  - Swatches are `<label>`s filled with the scale's step 9 (`backgroundColor: var(--${color}-9)`), laid out in a 10-column grid. Each wraps a native radio input. The colour name appears only in a tooltip.
- **GitHub.** Source: https://docs.github.com/en/get-started/accessibility/managing-your-theme-settings. **Secondary**: known only through a search summary of the current page, which the older Enterprise copies match. Re-read the page before quoting it.
  - Profile picture → Settings → Appearance. "Theme mode" is either a single theme or "sync with system".
  - With sync, you pick a day theme and a night theme separately. Themes are whole themes (including high-contrast and colour-blind variants), not accents.
  - Themes can also be switched from the command palette.
- **Linear.** Source: https://linear.app/docs/account-preferences. **Verified.**
  - Preferences → "Interface and theme": "Choose from our presets or create your own custom theme". You select Light or Dark modes or "system preference".
  - Custom themes are shared through https://linear.style (70+ themes).
- **shadcn/ui.** Source: `apps/v4/app/(app)/(create)/components/theme-picker.tsx` and `apps/v4/components/theme-selector.tsx` in https://github.com/shadcn-ui/ui. **Verified.**
  - The create page's trigger shows a small "Theme" caption, the current theme's name, and a round dot filled with that theme's dark `--primary`.
  - The menu is a radio group. Pointing at an item previews it (`setOverride`), and closing the menu clears the preview (`clearOverride`).
  - The docs site uses a plain `Select` of theme names.

**Pattern.**
- The picker sits top right, in a popover or panel, not in a settings page. Settings pages are for products with accounts.
- Mode (System / Light / Dark) and palette sit in the same surface, mode first in GitHub and Linear, accent first in Radix.
- Swatches are solid fills of the accent step as radio inputs, and the choice applies immediately with no confirmation.
- Names show as text (shadcn, Linear) or in a tooltip (Radix, with 26 swatches). With four palettes, a visible name beside each swatch fits.
- shadcn's preview-on-point is the one extra worth considering. With four options and instant apply, it adds little.

### 8.2 What this means for the five systems

- **Every palette keeps the status hues in their conventional families:** red danger, amber/yellow warning, green success. The palette may *move* a status colour within its family, away from the accent. That is what makes each palette one system.
- **Shared rules.** **Computed** and enforced by the generator. The checks pass for every value below.
  - `--ink` ≥ 7:1 on every surface and on `--accent-soft`.
  - `--ink-muted` ≥ 4.5:1.
  - `--accent-text` ≥ 4.8:1 on every surface and on `--accent-soft`.
  - Status text ≥ 4.5:1 on every surface and on its own soft background. Light-mode danger is set darker, ≥ 6.5:1, which matches today's `#a11f01` at 6.74:1 and helps CVD separation.
  - `--on-accent` ≥ 4.5:1 on both `--accent` and `--accent-hover`.
  - `--accent` and the focus-ring colour ≥ 3:1 against `--bg` and `--surface` (1.4.11).
  - In dark mode every text colour also reaches |Lc| ≥ 60 on every surface.
- **Neutrals keep today's OKLCH lightness ladder** and change only hue and a little chroma:
  - **Zinc** for Blue and Ink (unchanged).
  - **Warm cream** for Clay (85°, paper C 0.009–0.012).
  - **Slate** for Petrol (225°).
  - **Olive-grey** for Moss (105°).
- **Fills, scrim and shadows** use each palette's own `--ink` in light mode, with today's alpha values. Dark mode keeps today's white and black alphas.
- **`--focus-ring`** is `2px` of `--surface` (light) or `--bg` (dark) plus `2px` of `--accent` (light) or `--accent-text` (dark). Blue keeps today's `#0a84ff` in dark.
- **`--info` / `--info-soft`** stay aliases of the accent text and soft colours, except in **Clay**. There a clay "info" would read as a warning, so info gets its own muted blue (245°). This is the Claude app's own split, where interactive is blue and clay is brand.

**The five systems.**

- **Blue (today, fixed).** Only three dark text values change; light mode is unchanged.

Danger moves to **deep crimson** `#a21a44` (10°). Warning moves to **olive-yellow** `#776401` (96°, the Polaris "caution" family). Info is a slate blue `#427097`. Is it honestly possible?

### 8.5 Honest caveats

1. **Status hues now differ between palettes.** Success is 166° in Blue, 150° in Clay, 148° in Petrol and 172° in Moss. A reader who switches palettes sees "success" shift shade. It stays green in every palette, and the page "Colour means one thing" still holds within any one palette.
2. **Clay and Moss pass every contrast rule but are weaker for colour-blind readers.** Their accents sit between two status families. Blue, Ink and Petrol do not have this problem, apart from Petrol's thin tritan margin. If the site wants a palette that also *demonstrates* "Colour means one thing", the strongest are Blue, Ink and Petrol.
3. **Tinted neutrals change every surface**, so the §4 accent-only numbers do not apply to the full systems. Use §8.4.
4. **Outside the token file** (see §5, still true): focus-ring and knob values now come from the palette, but `precision.json` usage notes still describe Apple blue and white-on-accent in both themes. Ink dark needs the dark knob in this JSON.
5. **Not verified:**
   - claude.ai's web CSS. The page returns a Cloudflare challenge, so it was not fetched; the desktop app's bundled CSS was used instead.
   - Shopee's design-system documentation. Only the live CSS was read.
   - Why Polaris moved primary actions from green to black. That is inferred from two token versions, not from a Shopify statement.
