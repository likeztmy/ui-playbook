## When to use

A checkbox turns one option on or off, and the choice waits for the form to be sent. Use it for:

- **Options you can combine.** Any number of a set can be on: *PDF*, *PNG*, *SVG*.
- **One option sent with a form.** *Keep me signed in*, *Accept the terms*.
- **A hierarchy.** A parent box over its children, which line up under it. Apple prefers checkboxes over switches here: they align and group better.
- **Selecting rows.** A bare box in each row of a list or table.

Reach for something else when:

- **It takes effect at once.** A setting that applies the moment it changes is a Switch.
- **Only one can be chosen.** Radios for up to five, a Select for more.
- **It does something.** An action is a Button, even if it toggles a view.

## Anatomy

| Part | Token | Value |
| --- | --- | --- |
| Box | 16 × 16, `radius-xs` | 4 |
| Off | `surface` with a `line-strong` edge, ≥ 3:1 | |
| On, mixed | `accent` fill, `on-accent` mark | |
| Mark | Lucide `Check` or `Minus`, 12px, 2px stroke | 12 |
| Box to label | `space-2` | 8 |
| Label | body, 14 / 20 | 14 |
| Box offset | first line: (20 − 16) / 2 | 2 |
| Children indent | box + gap | 24 |

The label wraps the box, so the whole row is one target.

## Common mistakes

- **A checkbox that saves on the spot.** If nothing waits for a Save or Submit, it's a Switch.
- **Negative labels.** *Don't email me* turns checking into a double negative. Name what's on: **Email me about updates**.
- **Consent ticked in advance.** Marketing and data-sharing boxes start empty; checking them is the consent.
- **Disabling instead of explaining.** A greyed box with no reason is a dead end. Say why in the description, or hide it.

## Copy

- Label: what's true when it's checked, sentence case, no full stop: **Keep me signed in**.
- Group label: what the set is about: **Email me about**, **Export**.
- Description: the consequence, in a short sentence: **Anyone with the link can reply.**
