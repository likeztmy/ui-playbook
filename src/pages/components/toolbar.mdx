## When to use

A floating toolbar keeps a canvas's tools one click away without taking a column of the layout. Controls that belong to a form or a page are buttons in the content; rare actions go in a pull-down Menu; icons people wouldn't recognise need words.

## Details

### The current tool is a tint, not a fill

### Every tool is named by a tooltip

<ToolbarTips client:visible />

Icon-only tools carry an `aria-label` and a Tip with the same words. The toolbar shares one delay, so once a label has shown, its neighbours open at once.

## Variants

<ToolbarVariants client:visible />

One toolbar can hold all three, each in its own group behind a separator. What changes is how pressing behaves: tools switch a mode, toggles flip their own state, actions just run. After drawing one shape the tool returns to Select, as in Figma; holding a tool for many shapes is the exception.

## States

<ToolbarStates client:visible />

Tools are toggles in a group: arrow keys move between them, and the current one carries `aria-pressed`. On the canvas, the tool's letter switches to it.

## Common mistakes

- **Borders around groups.** Separate groups with a hairline (`line`), not boxes inside the box.
- **Two icon sets.** One set (Lucide) at one stroke. Mixing outline and filled icons, or two libraries, reads as two products bolted together.
- **Uneven inset.** More padding at the ends than on top pushes the end tools off the pill's centre line.

## Copy

- Tooltips name the tool, then its shortcut: **Rectangle** R. The name matches the `aria-label` word for word.
