## When to use

A menu holds actions or choices that don't need a permanent place on screen. One or two items are better as buttons; a form field's value is a Select; and once people search for an action, past about fifteen items, it wants a command menu.

## Kinds

What opens a menu decides what belongs in it. The same parts (icons, shortcuts, unavailable items) are right in one kind and wrong in another.

### Pull-down: commands from a button

<MenuLive client:visible />

Opened from a labelled button such as *Edit* or a *More* icon. Lists the commands for that area of the app, in the order people use them.

- **Icons** where each one clearly means its action, for every row of a group or for none.
- **Shortcuts** for the commands that have one. Leave the others blank; never invent one for the menu.
- **Unavailable commands stay, dimmed.** The layout stays put between contexts and people learn what exists. Here *Undo* is dimmed because there's nothing to undo.

### Context menu: actions on one object

Opened by right-click or long-press on a thing: a file, a row, a selection. It's already the shortcut, so it carries only the handful of actions that apply to this object now.

- **Three groups at most**, most-used first, destructive last. No title.
- **Icons** for familiar actions, the same ones used everywhere else in the product.
- **No keyboard shortcuts.** They belong in the pull-down and command menus. A web app with no menu bar may show them here so they can be learned somewhere; if so, only real ones, and in every context menu.
- **Unavailable actions are hidden**, not dimmed: the menu lists what this object can do.

### Choice: picking one value

Opened from a trigger that shows the current value (*Sort: Modified*). Each row is a value, not a command.

- **Radio items with a checkmark** on the current value. The checkmark marks state; highlight stays for the keyboard.
- **No icons, no shortcuts.** Values are words; decoration slows the scan.
- **A separator between independent choices**, such as the field and the order.
- Picking a value closes the menu and updates the trigger's label.

### Parts by kind

| Part | Pull-down | Context menu | Choice |
| --- | --- | --- | --- |
| Icon | All or none per group | Familiar actions, all or none | None |
| Shortcut | Where the command has one | None | None |
| Unavailable item | Dimmed | Hidden | — |
| Checkmark | On toggles | On toggles | On the current value |
| Submenu | One level, for a repeated term | One level | Rarely |
| Group label | When sections are distinct | Rarely | To name independent choices |
| Ellipsis | When more input follows | When more input follows | Never |

### Shortcuts are bare symbols in a column

<MenuShortcuts client:visible />

Check your fonts for the symbols before setting shortcuts in them. Geist has no ⌘ ⇧ ⌥ ⌫ ↵, and a font that borrows them from another face mixes weights, so here they're Lucide icons at a 1.25px stroke, a touch lighter than the row icons' 1.33px to sit with 13px text. Boxed keycaps belong in a command palette or a shortcuts sheet, where the key itself is the subject.

### The popup comes out of its trigger

<MenuMotion client:visible />

Opening grows from `enter-scale` (0.96) and `enter-offset` (4px) toward the trigger on the smooth spring, its origin at the trigger. Closing takes `duration-fast` with `ease-in`, no spring: once the user has chosen, nothing should hold them up. With reduced motion, only a short fade remains.

| Part | Token | Value |
| --- | --- | --- |

| Item height | `control-md` | 32 |
| Item padding, icon gap | `space-2` | 8 |
| Label | body-sm size, 13 / 18 | 13 |
| Shortcut | bare symbols, `ink-disabled`; last key in a fixed cell | 14 |
| Label to shortcut | `space-6`, at least | 24 |
| Surface | `surface-raised`, `shadow-md` | |

Icons are Lucide at 16px in `ink-muted`, turning `ink` on the highlighted row. Checkmarks lead the row, as on macOS: once any row in a menu can be checked, every row keeps that 16px column so the labels stay aligned. Submenu chevrons and shortcuts end the row.

## States

Arrows move the highlight, Right opens a submenu, and Space toggles a checkbox item without closing the menu. Disabled items in a pull-down stay focusable, so a screen reader still announces them. Pointer and keyboard share one highlight, with no transition in either direction.

## Common mistakes

- **A menu for one or two items.** Show them as buttons; the menu only hides them.
- **A group label that repeats the trigger.** A menu opened from *Edit* doesn't need an *Edit* heading. Separators group; add a label only when sections are genuinely distinct.
- **Destructive actions mid-list.** Put them in the last group, in `danger`, where a slip of the pointer is least likely to land.
- **Closing on every toggle.** A checkbox item stays open so several options can be set in one visit. A choice item closes: one value was picked.
- **Submenus inside submenus.** One level. If a submenu needs its own, it wants to be a separate menu or a dialog.

## Copy

- Commands are verbs or verb phrases: **Duplicate**, **Move to**. Choices are the values themselves: **Name**, **Modified**.
- An ellipsis means more input follows before the action completes: **Share…** opens a dialog, **Rename** edits in place.
- Sentence case, unlike Apple's title case: every label in the playbook is in sentence case.
- Keep one grammatical form within a menu.
