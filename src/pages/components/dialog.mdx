## When to use

A dialog stops everything for a decision or a short job, so the interruption has to pay for itself. A common action that can be undone wants a Toast with Undo; information alone belongs in place; a long or branching task wants a page; and a dialog never opens over another.

## Kinds

### Confirm: a decision before something permanent

For an uncommon action that can't be undone. An alert dialog: `dialog-sm` (400), a title that is the question, a sentence of consequence, and two buttons.

- **Cancel and a verb.** The verb names the result (*Delete project*), never *OK* or *Yes*.
- **Focus starts on Cancel**, so Enter backs out. Esc cancels too.
- **No outside dismissal.** A click on the scrim does nothing: the decision waits for a button, as Apple's alerts and the WAI-ARIA alert dialog do. A click that lands outside by accident shouldn't answer the question.
- **The one fill is `danger-fill`** when the action destroys. Apple keeps a deliberately chosen action in the default style; here it's red, so it reads as a stop before the hand gets there.

### Task: a short, scoped job

For a small job that needs input: rename, invite, new project. A dialog: `dialog-md` (560), a title that names the task, the fields, then Cancel and the action.

- **Focus starts in the first field**, with its text selected when editing.
- **Enter submits; Esc cancels.** The action button stays disabled until the input is valid.
- **The scrim cancels only an untouched dialog.** Once something is typed, a stray click outside does nothing.

### Kinds side by side

| Part | Confirm | Task |
| --- | --- | --- |
| Base UI part | `AlertDialog` | `Dialog` |
| Width | `dialog-sm` 400 | `dialog-md` 560 |
| Title | The question, with its object | The task, as a verb phrase |
| Initial focus | Cancel | First field |
| Enter | Activates the focused button | Submits |
| Scrim click | Nothing | Cancels when untouched |
| Fill | `danger-fill` or `primary` | `primary` |

## States

Focus moves inside and is trapped there; Tab cycles through the dialog only. On close, focus returns to the button that opened it.

## Common mistakes

- **Confirming the undoable.** Every extra *Are you sure?* trains people to click through the one that matters.
- **A dialog on arrival.** Nothing should interrupt someone who has just opened the page.
- **Explaining the buttons.** If the body says *Click Delete to delete*, the button labels have failed.
- **A dialog that scrolls.** Keep the title to two lines and the body to a sentence or two; longer belongs on a page.

## Copy

- Title: the decision or the task, specific: **Delete “Q4 roadmap”?**, **Rename project**. Never *Error* or *Are you sure?*.
- Body: what happens, in a sentence, only if the title doesn't already say it.
- Buttons: **Cancel**, always that word, and a verb for the action. The trigger ends in an ellipsis because more input follows: **Delete project…**
