## Find the press yourself

<PilotPress client:visible />

Three numbers make a press: how far it sinks, how fast it gets there, and how it comes back. The playbook lands on **0.97, down in 80 ms, back on a spring**. Anywhere from 0.96 to 0.98 is felt more than seen; at 0.95 and below people watch the button instead of the click. The way down has to beat the finger, so it's short; the way back can take its time, because by then the eye has moved on.

## Bigger things press less

<PilotEdge client:visible />

What the eye reads in a press is the edge moving in. At 0.97 a 100 px button's edge moves 1.5 px; a 280 px card's moves more than 4. So a card shouldn't share the button's scale. Past a button's width, give it the scale that moves its edge 1.5 px, `1 − 3 / width`, and a tag, a button and a card all feel like the same press.

## Take it with you

```css
.button {
  --spring: linear(
    0, 0.281, 0.615, 0.815, 0.917, 0.964,
    0.985, 0.994, 0.997, 0.999, 1
  );
  /* Name what changes, so a press doesn't drag the hover colour. */
  transition:
    background-color 120ms ease-out,
    scale 394ms var(--spring);
  -webkit-tap-highlight-color: transparent;
}

.button:hover {
  transition-duration: 0ms, 394ms;
}

.button:active:not(:disabled) {
  scale: 0.97;
  transition:
    background-color 0ms,
    scale 80ms ease-out;
}
```

- **`scale`, not `transform: scale()`.** The separate property composes with any `transform` the button already has, such as a toolbar sliding in.
- **Transition what changes, by name.** `transition: all` lets the press timing leak into the hover colour.
- **A disabled button doesn't press.** It can't run, so it shouldn't say it heard you.
- **Clear the tap highlight.** On iOS and Android a grey flash covers the press otherwise.
- **Shortcuts skip it.** An action run from the keyboard has no button under a finger; don't play the press on a button nobody touched.
